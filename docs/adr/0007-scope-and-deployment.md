# ADR 0007 — Scope: a portfolio demo, not a production deployment

- **Status:** Accepted
- **Date:** 2026-10-16
- **Deciders:** project author

## Context

This project exists to demonstrate engineering practice — layered architecture,
testing, CI, reproducible environments — on a realistic domain (a 42-style
student progress dashboard). It is not a product with real users or data. That
scope should be stated explicitly, because several otherwise-suspect choices are
deliberate here and would need to change in a real deployment.

## Decision

Treat the app as a **local, reproducible demonstration**. Concretely:

- **No production build/deploy pipeline.** The frontend runs under Vite's dev
  server; the API under uvicorn with `--reload`. The goal is `nix develop && just
dev`, not a container image behind a reverse proxy.
- **Demo credentials, not secrets.** The seeder creates fictional students that
  all share the password `42cursus!`. No real credentials are stored, and there
  is no signup.
- **Seed data is synthetic and deterministic.** All data is generated by a
  seeded RNG (ADR 0001); the API is effectively read-only at runtime.
- **Tokens are stateless and non-revocable** (ADR 0002). There is no denylist;
  short access-token lifetimes bound the risk. A production system with
  logout-everywhere or compromise response would need server-side revocation.
- **Auth via query-param token for SSE** (ADR 0003) is accepted for the demo.
- **Everything is reproducible via Nix**, so "it works on my machine" is the
  same environment CI uses.

## Consequences

- **Positive:** the whole stack starts from one command with zero external
  services beyond Docker for Postgres; the seeded demo is instantly explorable.
- **Positive:** reviewers can run the exact CI environment locally.
- **Negative:** none of the hardening a real deployment needs is present
  (TLS, secret management, rate limiting, revocable sessions, migrations gating,
  observability wiring). These are out of scope, and this ADR is the place that
  says so.
- **Follow-up if it ever shipped:** add a production build + container images,
  a secrets story, token revocation, and real user provisioning.
